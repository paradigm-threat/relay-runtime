# Debugging relay-runtime in Web View

For CleverScript language limits and parse/runtime errors, see [docs/CLEVERSCRIPT.md](../../docs/CLEVERSCRIPT.md).

## Current Debug Options

### 1. **Chrome DevTools Network Panel** ✅
All `fetch()` calls automatically appear in the Network panel when DevTools is open. No integration needed - it's built into the browser.

**How to use:**
- Open DevTools (F12 or Cmd+Option+I)
- Go to Network tab
- All fetches (theme.yaml, WASM module, etc.) are automatically recorded
- Click any request to see headers, response, timing, initiator

### 2. **Console Logging** ✅
- **Errors**: Always logged to `console.error` with `[relay-runtime]` prefix
- **Verbose mode**: Set `VERBOSE = true` in `index.html` to log:
  - Each hook execution
  - File loads
  - Fetch operations

### 3. **WASM Source-Level Debugging** ⚠️ (Requires setup)

**Breakpoints in WASM are possible** but require:
1. **Compile with debug symbols**: Add `-g` flag to `wasm-pack build`
   ```bash
   wasm-pack build --target web --out-dir pkg -- --features wasm -g
   ```
2. **Install Chrome extension**: [C/C++ DevTools Support (DWARF)](https://chrome.google.com/webstore/detail/cc-devtools-support-dwar/gnhhdgbaldcilmgcpfddgdbkhjhohfcj)
3. **Source maps**: Currently not generated by default

**Limitations:**
- `debugger;` statements in Rust code won't work (Rust doesn't have `debugger;`)
- Breakpoints must be set in DevTools Sources panel on the `.wasm` file
- Requires DWARF debug info in the compiled WASM

### 4. **JavaScript Breakpoints** ✅
You can use `debugger;` in the JavaScript host code:

```javascript
async function main() {
  debugger; // Pauses here in DevTools
  await init();
  // ...
}
```

Or set breakpoints in DevTools Sources panel on `index.html`.

### 5. **Performance Profiling** ✅
- Open DevTools → Performance tab
- Click Record
- Interact with the page
- Stop recording to see timeline with WASM execution

### 6. **Memory Inspector** ✅
- DevTools → Memory tab
- Take heap snapshot to inspect WASM memory
- Use Memory Inspector for ArrayBuffer/TypedArray inspection

## Recommended Debugging Workflow

### For Network Issues:
1. Open DevTools → Network tab
2. All fetches are automatically visible
3. Use filters to find specific requests
4. Check Response/Preview tabs for content

### For Runtime Errors:
1. Errors automatically log to console with `[relay-runtime]` prefix
2. Check Console tab in DevTools
3. Stack traces show WASM function names (if debug symbols present)

### For Performance:
1. DevTools → Performance tab
2. Record while running hooks
3. Look for WASM execution in the timeline
4. Use Performance marks (already added for fetches)

### For Source-Level Debugging:
1. Rebuild with debug symbols: `wasm-pack build --target web --out-dir pkg -- --features wasm -g`
2. Install DWARF extension
3. Set breakpoints in DevTools Sources panel on `.wasm` file
4. Step through Rust source (if available)
